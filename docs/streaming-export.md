# 流式模型导出

右键导出模型、仅带动画的模型、世界或动画时，现在会自动打开 Export Session 并开始导出，不再等整个目录加入 Queue，也不需要再次点击 Export。导出开始时读取一次输出目录与选项；运行期间修改选项用于下一次导出。

## 内存与扫描方式

- 使用单个模型/资源作为保守的处理批次。当前资源及依赖完成转换、写盘后，扫描器才继续，避免扫描速度超过写盘速度导致队列增长。
- 材质、贴图、匹配动画按依赖逐项处理。会话不保存所有已完成的 exporter 或 ExportResult，完成的包和转换缓冲区失去引用后可由 .NET GC 回收；不对每个模型强制进行全堆回收。
- 动画匹配索引每个会话、每个 provider 构建一次，只保存骨骼与动画路径，不保存加载后的动画、骨骼或包。先检查导出类型，再加载匹配的动画数据。普通骨骼模型先写出模型，再收集动画；“仅带动画的模型”需要先完成一次索引才能判断哪些模型符合条件。
- 去重包含目标分组目录。同一材质或动画需要复制到不同模型目录时，不会被当作同一次输出跳过。
- 全部批量包内对象都会被检查，不使用 JSON 预览分页，也不为批量导出生成 JSON 预览。
- 会话结束、取消或异常时清理队列、去重路径、动画索引和运行状态。取消会向扫描和导出传递；已经完成的文件保留。

## 进度与日志

扫描尚未结束时总量未知，因此显示不定进度条和已完成/成功/失败计数，不显示误导性的 ETA。主界面和 Export Session 的取消按钮均可停止本次操作。扫描失败也计入失败数。

界面最多保留最近 200 个资源、每个资源 20 条日志，待显示日志最多 1000 条；只保留日志文本与异常描述，避免异常对象间接持有资源数据。完整日志沿用应用现有的日志文件。关闭的 Snooper 导出窗口不会积压其他导出任务的日志。

“Export Immediately”仍控制其他类型的旧队列导出，模型、世界和动画始终使用本次流式流程。

## 验证

`CUE4Parse.Tests/StreamingExportTests.cs` 的 21 项测试通过，包括：

- 扫描尚未完成时首个文件已经写盘，以及嵌套/循环依赖处理。
- 同一输出位置去重，不同分组位置分别写出。
- 取消、依赖内取消、扫描错误、单个转换失败后的清理与会话复用。
- 并发启动、外部插入、运行中清空队列的保护。
- 累计 512 个各 2 MiB 的模拟加载对象（总计 1 GiB）；在扫描未结束时分段触发测试 GC，确认已处理 exporter 可回收，队列归零。这是引用保留测试，不是大型游戏的真实峰值内存测量。
- 仓库测试资源的全 LOD 导出，包含材质和贴图；ActorX、UEFormat、glTF、USD 的流式结果与队列结果逐文件比较一致。
- 动画索引在会话内复用、会话后清理，以及 Montage 过滤。
- 测试资源中的动画压缩数据暂不受当前转换器支持；新旧流程的失败资源和错误消息一致，新流程仍先写出模型，再报告动画转换失败。没有将这些动画当成成功导出。

## 边界

内存仍取决于当前包、单个模型及其依赖、解码缓冲区和文件索引。一个极大的包/模型/世界仍可能耗用较多内存；这里没有提供固定字节数的内存上限。去重路径和动画路径索引仍会随资源数增长，但不持有全游戏的已解码模型数据。运行时何时归还工作集由 .NET 和操作系统决定。

尚未在用户的大型游戏资源上进行端到端导出、峰值内存测量或逐模型视觉验收。本次交付是导出流程的代码改进，不是模型提取成品验收。原有依赖漏洞、可空类型和过时 API 等构建警告未在本次修改中处理。
