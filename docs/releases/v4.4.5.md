## FModel v4.4.5：流式导出与内存优化

本版本解决导出大目录时，先把全部模型加载进 Queue、等待用户再次点击 Export，导致内存持续增长的问题。右键导出模型、仅带动画的模型、世界或动画后，现在会自动开始扫描和导出，并打开进度窗口。

### 更新内容

- **边扫描边导出**：以单个资源为保守处理批次，完成模型及依赖的转换、写盘后再继续扫描，避免积压已加载对象。
- **释放已完成资源的引用**：会话不保留全部 exporter 或导出结果；完成的包和转换缓冲区可由 .NET GC 回收。取消、异常和结束时清理队列与会话索引。
- **动画匹配优化**：每次会话、每个 provider 只建立一次骨骼—动画路径索引，不再为每个骨骼模型重新扫描全游戏。普通模型先写盘，再处理匹配动画。
- **保留分组依赖**：同一材质、贴图或动画输出到不同模型目录时分别处理；相同目标位置去重。
- **批量导出更完整**：检查包内全部对象，不再使用 JSON 预览分页，也不为批量模型导出生成 JSON 预览。
- **进度与取消**：显示成功、失败、已完成数量；扫描期间使用不定进度条，两个取消入口均能停止本次操作。扫描异常计入失败统计。
- **限制界面日志占用**：最多保留最近 200 个资源、每个资源 20 条日志；完整日志沿用应用日志文件。关闭的 Snooper 窗口不会积压其他任务的日志。
- **同步上游**：包含此前合入的上游目录树性能改进和解析器更新，保留本分支的动画绑定与分组导出定制。
- **修复发布流程**：正式发布统一使用 .NET 10，补充 GitHub Release 写入权限，修复 QA 发布阶段的 HTTP 403。

### 下载与运行

下载 `FModel-win-x64.zip`，解压后运行 `FModel.exe`。这是 Windows x64、依赖框架的单文件版本，需要安装 **.NET 10 Desktop Runtime（x64）**。

`SHA256SUMS.txt` 提供压缩包校验值。导出前请设置输出目录和导出选项；模型、世界和动画无需再次点击 Export。“Export Immediately”继续控制其他类型的旧队列导出。

### 验证结果

- 流式导出相关 **21 项自动化测试通过**，覆盖及时写盘、依赖去重、取消、失败统计、并发保护和会话复用。
- 累计创建 512 个各 2 MiB 的模拟加载对象（共 1 GiB），确认扫描尚未结束时，已处理 exporter 可以被回收。
- 仓库测试模型包含全 LOD、材质和贴图；ActorX、UEFormat、glTF、USD 的新旧流程输出逐文件比较一致。
- 代码已通过本地 Release 单文件发布构建；本发布附件由 GitHub Actions 从发布提交构建，并附 SHA-256 校验值。

### 已知限制

- 尚未对用户的大型游戏进行端到端峰值内存测量；单个超大包、模型、世界及其依赖仍可能占用较多内存。本版本没有固定字节数的内存上限。
- “仅带动画的模型”仍需先完成一次路径索引，才能判断模型是否符合条件。路径索引和去重记录仍会随资源数量增长。
- 仓库的一组测试动画使用当前转换器不支持的压缩数据，新旧流程都会报告失败；本次未扩展动画压缩格式支持。模型会先写出，动画失败会被单独统计。
- 原有依赖漏洞、可空类型和过时 API 等构建警告未在本版本中全部处理；没有进行逐模型视觉验收。
